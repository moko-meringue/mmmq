producer · broker · consumer 세 모듈의 기능, 설정, 사용 예제, API 레퍼런스를 한 곳에 모았습니다. 왼쪽 사이드바 또는 아래 카드에서 시작할 모듈을 골라 주세요.

모듈 간 통신 흐름

producer가 보낸 메시지는 broker를 거쳐 consumer에 도달합니다. 각 단계는 서로 다른 프로토콜과 책임을 가집니다.

producer → broker → consumer 
┌──────────┐   POST /mmmq/messages      ┌───────────────────────────┐   POST /mmmq/messages       ┌──────────┐
│ producer │ ─────────────────────────▶ │           broker           │ ────────────────────────▶  │ consumer │
└──────────┘        Message             │                             │  Message + mmmq-consumer-id └──────────┘
     ▲                                  │ 1. 디스크에 기록 후 ACK/NACK  │        헤더로 라우팅              │
     │            ACK / NACK            │ 2. 토픽 패턴 매칭 → Dispatcher│                                 │
     └──────────────────────────────────│ 3. Dispatcher별 독립 재전송   │◀────────────────────────────────┘
                                         └───────────────────────────┘        ACK / NACK

producer는 Message를 broker로 보내고, broker의 ACK/NACK 응답만 확인합니다. consumer가 실제로 처리를 마쳤는지는 기다리지 않습니다.
broker는 수신한 메시지를 디스크에 기록해 응답한 뒤, 토픽 패턴이 일치하는 모든 Dispatcher를 통해 각자 독립적으로 consumer에게 전송합니다.
consumer는 요청 헤더의 mmmq-consumer-id로 등록된 핸들러를 찾아 동기적으로 실행하고, 성공하면 ACK, 실패하면 NACK으로 응답합니다.
consumer가 NACK을 보내거나 응답하지 않으면, 해당 Dispatcher가 재시도합니다 — 다른 Dispatcher나 다른 consumer의 소비에는 영향을 주지 않습니다.

모듈

각 모듈은 Spring Boot 애플리케이션에 의존성으로 추가하는 라이브러리입니다. core는 공통 타입을 제공하며, producer · broker · consumer는 각각의 애플리케이션에 따로 추가해 사용합니다.

core
모든 모듈이 공유하는 핵심 타입을 정의합니다. 메시지, 토픽, ConsumerId, 응답 등 도메인 원시 타입을 모아둡니다.
producer
메시지를 broker로 보내는 모듈입니다. 동기로 동작하며, 전달에 실패하면 자동으로 재시도합니다.
broker
메시지를 디스크에 보관하고 consumer에게 전송하는 모듈입니다. 토픽 패턴이 매칭되는 Dispatcher마다 독립된 송신 경로를 만듭니다.
consumer
broker가 보낸 메시지를 ConsumerId로 등록된 핸들러에 라우팅하는 모듈입니다.
