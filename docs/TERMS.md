# 문서 용어 사전

> mmmq docs에서 같은 개념을 같은 단어로 설명하기 위한 기준입니다.

## 저장과 영속화

- **저장**: 파일, 큐, 인덱스, 체크포인트에 데이터를 쓰는 동작을 설명할 때 사용합니다.
  - 예: 메시지를 세그먼트 파일에 저장합니다.
  - 예: 오프셋 인덱스에는 entry 시작 byte 주소가 저장됩니다.
- **영속화**: 장애나 재시작 후에도 데이터가 디스크에 남는 내구성 보장을 설명할 때 사용합니다.
  - 예: `ACK`을 받은 메시지는 디스크에 영속화된 상태로 남습니다.
  - 예: 메시지 영속화 구조.
- **보관**: 세그먼트나 토픽 큐가 이미 저장된 메시지를 일정 기간/범위로 담고 있다는 의미에만 사용합니다.

## 조회와 읽기

- **조회**: 오프셋을 기준으로 어떤 메시지를 가져올지 찾는 논리적 동작을 설명할 때 사용합니다.
  - 예: `Dispatcher`는 체크포인트의 오프셋부터 메시지를 조회합니다.
  - 예: 메시지 조회 과정.
- **읽기**: `.idx`, `.mmm`, byte, entry처럼 파일이나 바이트를 실제로 읽는 저수준 동작을 설명할 때 사용합니다.
  - 예: `.idx` 파일의 48 byte 위치에서 8 byte long 값을 읽습니다.
  - 예: `.mmm` 파일에서 entry frame을 읽습니다.

## 소비, 처리, 전송

- **소비**: `Dispatcher`가 토픽 큐의 메시지를 조회하고 consumer 전송까지 진행하는 전체 흐름을 설명할 때 사용합니다.
  - 예: 토픽 큐에 메시지가 들어오면 `Dispatcher`가 메시지 소비를 시작합니다.
- **처리**: consumer 핸들러 실행 결과나 `ACK` 이후 완료 상태를 설명할 때 사용합니다.
  - 예: consumer가 `ACK`을 반환하면 처리 완료로 간주합니다.
- **전송**: 네트워크를 통해 메시지를 보내는 동작을 설명할 때 사용합니다.
  - 예: producer는 broker로 HTTP 요청을 전송합니다.
  - 예: `Dispatcher`는 메시지를 consumer에게 전송합니다.
- **전달**: 라우팅 결과를 추상적으로 말할 때만 제한적으로 사용합니다. HTTP 요청/응답에는 전송을 사용합니다.

## 생산과 발행

- **생산**: broker 내부 파이프라인에서 producer 요청을 받아 토픽 큐 저장 대상으로 만드는 단계를 설명할 때 사용합니다.
  - 예: 메시지 생산 단계.
- **발행**: producer 사용자가 `produce(Message)`로 메시지를 보내는 외부 API 행위를 설명할 때 사용합니다.
  - 예: producer는 메시지를 발행합니다.

## 등록과 생성

- **생성**: 객체, 큐, 파일, 디렉터리를 새로 만드는 동작을 설명할 때 사용합니다.
  - 예: 토픽 큐가 없으면 새 `TopicQueue`가 생성됩니다.
- **등록**: 이미 만들어진 핸들러, 빈, 큐, 설정을 시스템이 인식하도록 추가하는 동작을 설명할 때 사용합니다.
  - 예: `Dispatcher` 빈을 등록합니다.

## 기타 표기

- **디렉터리**로 통일합니다. `디렉토리`는 사용하지 않습니다.
- **broker**, **producer**, **consumer**는 일반 명칭일 때 영문 소문자로 씁니다.
- **byte**는 파일 위치와 크기를 설명할 때 영문으로 씁니다.
- **fsync**는 디스크 동기화 동작을 직접 설명할 때만 사용합니다.
- **커밋**은 `Dispatcher`의 체크포인트를 다음 오프셋으로 옮기는 동작에만 사용합니다.
