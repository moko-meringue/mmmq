PILLARS

왜 mmmq인가

신뢰할 수 있는 메시징을 위한 네 가지 기준을 두고 만들어 갑니다.

01 · RELIABILITY

신뢰성

메시지가 손실되지 않고, 잘못된 consumer에게 전송되지 않습니다.

02 · DURABILITY

내구성

예기치 못한 장애와 재시작 후에도 메시지는 살아남습니다.

03 · PERSISTENCE

영속화

디스크에 안전하게 기록되어 사라지지 않습니다.

04 · THROUGHPUT

높은 처리량

안정성을 잃지 않으면서 빠르게 흐릅니다.

AT A GLANCE

간단하게 시작합니다

의존성을 추가하고 빈을 등록한 뒤, 한 번의 메서드 호출로 메시지를 발행합니다.

Java 
@Service
public class OrderEventPublisher {

    private final Producer producer;

    public OrderEventPublisher(Producer producer) {
        this.producer = producer;
    }

    public void publish(long orderId) {
        producer.produce(new Message(
            new Topic("order.created"),
            Map.of("id", orderId)
        ));
    }
}
  1. 1
    JitPack 저장소와 producer 의존성을 추가합니다.
  2. 2
    @Configuration에서 Producer 빈을 등록합니다.
  3. 3
    주입받은 Producer의 produce(Message)를 호출하면 끝입니다.
  4. 4
    실패 시에는 ProduceException이 던져집니다.
MODULES

세 모듈로 구성됩니다

각 모듈은 독립적으로 의존성에 추가해 사용합니다.

producer
broker로 메시지를 보내는 클라이언트. 빌더로 재시도 정책을 설정하고, 실패 시 ProduceException을 던집니다.

broker
메시지를 디스크에 저장하고 Dispatcher로 라우팅합니다. TopicQueue, 세그먼트, 체크포인트를 포함합니다.

consumer
@MMMQListener와 MMMQListener<T> 두 가지 방식으로 핸들러를 등록합니다. 패턴 매칭과 ACK/NACK는 자동입니다.
